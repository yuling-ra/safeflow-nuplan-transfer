# 多进程并行加速说明

## 性能提升

你的系统有 **32 个 CPU 核心**，多进程并行可以带来显著加速！

### 预期加速效果

| 测试规模 | 配置数 | 单进程时间 | 多进程时间 (16-28 workers) | 加速比 |
|---------|--------|-----------|---------------------------|--------|

## 工作原理

### 并行策略

1. **任务分配**: 将所有配置组合分配给多个 worker 进程
2. **独立执行**: 每个 worker 独立运行一个配置的完整测试
3. **结果汇总**: 所有 worker 完成后，主进程汇总结果

### 为什么有效？

- **CPU 密集**: PCA 计算主要是矩阵运算，CPU 密集
- **独立任务**: 每个配置互不依赖，完全并行
- **无 IO 瓶颈**: 数据在内存中，每个进程独立加载

## 配置建议

### Worker 数量选择

你的系统（32 核，限制使用 18 核）推荐配置：

```bash
# 小规模测试（快速验证）
--num-workers 12    # 使用 38% 总核心，67% 可用核心

# 中等规模测试
--num-workers 16    # 使用 50% 总核心，89% 可用核心

# 大规模测试
--num-workers 18    # 使用 56% 总核心，100% 可用核心

# 完整测试（最大化利用）
--num-workers 18    # 最大使用 18 核心
```

### 为什么限制在 18 核？

1. **资源预留**: 为其他任务和系统进程保留资源
2. **避免过载**: 防止系统过载影响稳定性
3. **内存带宽**: 18 个进程已经接近内存带宽上限
4. **性价比**: 18 核已能提供 ~15x 加速，更多核心收益递减

## 自定义 Worker 数量

### 方法 1: 修改脚本

编辑 `run_sweep_*.sh`，修改 `--num-workers` 参数：

```bash
# 例如：使用 12 个 workers
python3 sweep_multigroup_pca.py \
  ... \
  --num-workers 12
```

### 方法 2: 命令行指定

```bash
python3 sweep_multigroup_pca.py \
  --data ../Compress_Test/test_complete.npz \
  --out ./results \
  --num-workers 20 \
  --Kq 256 384 \
  --Kdq 128 192 \
  --Ktau 128 192 \
  --latent-triplets "400,50,50" "360,70,70" \
  --filters none
```

### 方法 3: 自动模式

不指定 `--num-workers`，代码会自动使用 `CPU核数 - 1`：

```bash
python3 sweep_multigroup_pca.py \
  --data ../Compress_Test/test_complete.npz \
  --out ./results \
  ...
  # 自动使用 31 个 workers
```

## 性能优化技巧

### 1. 内存管理

每个 worker 会加载完整数据集，确保有足够内存：

```
所需内存 ≈ worker数 × 数据集大小 × 1.5
         ≈ 18 × 3GB × 1.5
         ≈ 81 GB
```

如果内存不足，减少 worker 数量。

### 2. 批量大小

对于小规模测试（配置数 < worker数），并行效果有限。

**建议**: 
- 配置数 < 10: 使用 4-8 workers
- 配置数 10-50: 使用 12-16 workers
- 配置数 > 50: 使用 16-18 workers

### 3. IO 优化

所有结果文件独立写入，无 IO 竞争。但在 HDD 上可能稍慢，SSD 最佳。

## 故障排除

### 问题 1: 进程卡住

**原因**: 内存不足或 CPU 超载

**解决**: 减少 worker 数量
```bash
--num-workers 8  # 从 28 降到 8
```

### 问题 2: 速度没有提升

**原因**: 可能是单个配置太快，调度开销占比大

**解决**: 正常现象，对于快速任务（<5秒），加速比有限

### 问题 3: 某些配置失败

**现象**: 输出显示 `✗` 标记

**解决**: 查看错误信息，通常是参数问题（如 r 超过最大成分数）
